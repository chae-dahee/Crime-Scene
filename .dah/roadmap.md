# 디벨롭 방향

치팅 방지, 시나리오 품질, 수익화, 플랫폼 확장 방향을 정리한 문서다. 참고용 초안이며, 구현이 이 문서와 달라도 무관하다.

## 배경

정적 페이지에서는 정답, 엔딩, 대사, 단서가 모두 클라이언트 코드에 들어 있다. AI에게 브라우저 분석을 시키면 소스에서 정답을 바로 찾을 수 있고, 정답 키만 숨기더라도 대사와 단서 데이터 전체를 읽어 추리할 수 있다. 그래서 진행하지 않은 콘텐츠를 클라이언트에 내려보내지 않도록 시나리오 데이터와 판정을 서버로 옮겼다.

모바일·Steam 빌드는 게임 파일이 사용자 기기에 설치되어 클라이언트 측 숨김이 더 약해진다. 치팅 방지와 플랫폼 확장은 같은 서버를 공통 기반으로 삼는다.

LLM 심문은 시험 결과 고정 대사를 말투만 바꾸는 수준에 그쳤고, 지연과 비용, 호칭이나 말투가 어긋나는 문제를 더했다. 퍼즐의 정확성과 일관성을 우선하기 위해 LLM 기능은 제거하고 고정 데이터만 사용한다.

## 전제

- public 저장소 노출은 고려하지 않는다.
- git 이력은 공개 상태로 유지한다. 이미 커밋된 시나리오의 정답과 대사는 이력에 남는다.

## 서버 구성

서버는 Cloudflare Workers와 TypeScript로 구현한다. 세션 상태는 SQLite 기반 Durable Objects에 두는데, 목숨 차감처럼 순서가 중요한 상태를 세션 단위로 일관되게 처리하기 위해서다. KV는 최종 일관성 모델이라 세션 상태 저장에 쓰지 않는다.

프론트엔드는 GitHub Pages에서 Cloudflare Pages(`프로젝트.pages.dev`)로 옮긴다. GitHub Pages는 온라인 비즈니스를 위한 무료 호스팅으로 쓰는 것을 허용하지 않아 광고를 붙이기 어렵다. AdSense는 루트 도메인이나 Public Suffix List(PSL)에 있는 플랫폼의 서브도메인만 사이트로 등록하는데, `pages.dev`는 PSL에 있고 `프로젝트.pages.dev`가 그 바로 아래 한 단계라 사이트 단위와 실제 주소가 일치한다. 서버의 `workers.dev` 주소는 계정 서브도메인 아래 두 단계라 사이트 단위가 실제 주소와 어긋나므로 프론트엔드 주소로 쓰지 않는다.

- 프론트엔드와 서버의 출처가 달라 CORS는 유지하고, 서버의 `ALLOWED_ORIGINS`에 `pages.dev` 주소를 넣는다.
- `server/` 디렉터리는 Pages 배포 대상에서 제외해 시나리오 데이터가 공개되지 않게 한다.
- 자체 도메인은 AdSense 승인이나 호스팅 이전에 문제가 생길 때 다시 검토한다.

## 단계별 방향

### 1단계. 서버 이전 (완료)

시나리오 데이터와 판정 로직을 서버로 옮겼다. 클라이언트는 조사, 제시, 고발 같은 행동만 보내고 결과 텍스트만 받는다.

- 서버가 세션 상태를 관리해 획득하지 않은 단서는 제시할 수 없다.
- 목숨(촛불) 횟수를 서버가 관리해 고발 조합 대입을 막는다.

### 2단계. 시나리오 품질 점검

게임의 핵심 가치는 퍼즐의 완성도이므로 출시 전에 시나리오 3개를 같은 기준으로 점검한다.

- 범인만 거짓말을 한다. 범인이 아닌 용의자가 말을 피한 단서에는 두 번째 제시 반응을 두어 사실을 털어놓게 한다.
- 범인을 확정하는 결정적 증거가 있다.
- 단서를 얻는 흐름에 서사적 이유가 있다. 같은 단서를 반복 제시했다고 관련 없는 물건이 생기지 않는다.

### 3단계. 웹 출시

스토어 심사가 없는 웹으로 먼저 출시한다. 플레이 데이터 측정은 따로 구현하지 않는다. 광고 노출과 수익은 Ad Manager·AdSense 대시보드에서 확인하고, 플레이어가 막히는 지점은 플레이 테스트와 피드백으로 파악한다.

### 4단계. 힌트 광고

보상형 힌트 광고를 붙인다. 설계는 아래 수익 모델을 따르고, 구현 설계는 `.dah/hint-ad.md`에 둔다.

### 5단계. 모바일

App Store와 Google Play에 앱 래퍼(Capacitor 등)로 출시한다. 광고 SDK는 웹과 달리 모바일용(AdMob 등)으로 교체해야 한다.

### 6단계. Steam (미정)

Steam 출시 여부는 미정이다. Steam onboarding 문서는 게시하면 안 되는 콘텐츠로 "Applications with advertising-based business models"를 명시하므로, 출시한다면 광고 대신 유료 판매나 힌트 인게임 구매로 수익을 내야 한다.

## 수익 모델

힌트를 보상형 광고로 제공한다. 광고를 보지 않아도 문제를 풀 수 있어야 하고, 힌트를 원하는 플레이어만 광고를 시청한다.

### 설계

지금은 같은 용의자에게 반응 없는 단서를 두 번 제시하면 조사할 곳을 가리키는 무료 힌트가 나온다. 광고 힌트를 붙이면 무료 힌트와 역할이 겹치므로 둘의 경계를 먼저 정해야 한다. 무료 힌트를 유지해 광고 없이도 완주할 수 있게 하고, 광고 힌트는 플레이어가 원할 때 바로 받는 즉시성으로 가치를 만드는 방향을 기본안으로 둔다.

- 무료 힌트는 지금처럼 반복 시도 뒤에 조사할 장소만 가리킨다.
- 광고 힌트는 플레이어가 원할 때 즉시 받으며, 무료 힌트보다 구체적으로 다음 단서를 얻는 방법을 알려준다.
- 보상 지급 여부는 서버가 판정한다. 클라이언트가 보상을 직접 열면 광고 없이 힌트를 얻는 우회가 생긴다.
- 광고 후보를 촛불 회복으로 넓힐지는 고발 조합 대입 방지와 충돌하므로 보류한다.

Apple 3.1.1은 돈을 받고 기능을 열 때 인앱 구매를 요구하므로, 힌트를 판매하지 않으면 문구상 인앱 구매는 필수가 아니다. 3.2.2(x)는 광고 시청에 대한 보상을 허용한다. 다만 3.1.4는 광고 활동을 기능 해제 조건으로 요구하는 것을 금지하므로, 힌트를 광고로만 열 수 있는 기능으로 볼지는 심사 해석에 달려 있다. 무료 힌트를 유지하는 기본안은 이 해석 위험을 줄인다.

### 플랫폼별 수수료와 수익 배분

아래 값은 2026-11-23에 각 공식 문서에서 확인했다. 지역별 예외와 프로그램 가입 조건이 있으므로 출시 시점에 다시 확인한다.

- 웹 광고(Google)
  - AdSense for Content는 광고주 플랫폼 수수료를 뺀 수익의 80%를 게시자에게 준다. Google Ads로 구매된 디스플레이 광고 기준으로는 게시자가 약 68%를 받는다.
  - 웹 보상형 광고는 Google Ad Manager에서 지원한다. 디스플레이 광고는 보상 지급 전에 최소 7초 노출되어야 하고, 옵트인 화면과 보상 지급은 게시자가 구현한다. Ad Manager의 수익 배분율은 공개 문서에 없다.
  - 웹 보상형 광고는 확대·축소가 중립인 모바일 최적화 페이지에서만 지원된다. PC 브라우저에서는 광고 힌트를 제공할 수 없다.
  - Ad Manager 가입에는 AdSense 계정이 필요하다. AdSense는 사이트 없이 먼저 가입할 수 있다.
- App Store
  - 개발자 프로그램은 연 99 USD다.
  - 디지털 상품 수수료는 30%이고, Small Business Program(전년도 수익 100만 USD 이하) 가입 시 15%다.
- Google Play
  - 개발자 계정 등록비는 1회 25 USD다.
  - 연 100만 USD까지 15%(15% 등급 가입 필요), 초과분은 30%다.
  - EEA·영국·미국은 2026-06-30, 호주·일본은 2026-09-30부터 새 구조가 적용된다. 연 100만 USD까지는 10%에 결제 수수료 5%가 붙는다.
- Steam
  - 앱마다 Steam Direct 수수료 100 USD를 내고, 조정 총수익 1,000 USD에 도달하면 돌려받는다. 수수료 납부 후 21일이 지나야 출시할 수 있다.
  - 수익 배분율은 공식 문서에서 확인하지 못했다.

광고 수익만 쓰는 동안에는 스토어 수수료가 적용되지 않는다. 스토어 수수료는 힌트 판매나 유료 앱처럼 결제가 생길 때 해당한다.

### 인프라 무료 한도

운영 비용은 아래 무료 한도 안에서 시작한다. 값은 2026-11-23에 공식 문서에서 확인했다.

- Cloudflare Workers Free: 하루 100,000 요청, 호출당 CPU 10ms다.
- Durable Objects Free(SQLite 백엔드만 사용 가능): 하루 100,000 요청, 하루 13,000 GB-s, 하루 행 읽기 500만·행 쓰기 100,000, 전체 저장 5GB다.
- Cloudflare Pages Free: 정적 파일 요청은 무료·무제한이다. 사이트당 파일 20,000개, 파일당 25MiB, 월 빌드 500회, 동시 빌드 1개다. 이 값은 2026-11-24에 확인했다.

게임 행동 하나는 CORS 사전 요청(OPTIONS)과 본 요청(POST)으로 Workers 요청 2개를 쓴다. 따라서 Workers 한도 기준으로 하루 약 50,000회 행동까지 무료 플랜으로 운영할 수 있다.

## 미결 사항

- AdSense 사이트 등록은 승인을 보장하지 않는다. 화면 대부분이 게임이고 글이 적어 콘텐츠 심사를 통과할지 확인해야 한다.
- Ad Manager는 대형 게시자용으로 안내되어 있어 가입 승인 여부를 확인해야 한다.
- 무료 힌트를 유지하는 기본안이 Apple 3.1.4 심사를 통과하는지 출시 전 App Review 문의를 검토한다.
- Steam 출시 여부와 수익 배분율을 확인해야 한다.
