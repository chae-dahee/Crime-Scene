# 디벨롭 방향

치팅 방지, LLM 심문, 수익화, 플랫폼 확장 방향을 정리한 문서다.

## 배경

현재 게임은 정적 페이지라서 정답, 엔딩, 대사, 단서가 모두 클라이언트 코드에 들어 있다. AI에게 브라우저 분석을 시키면 소스에서 정답을 바로 찾을 수 있고, 정답 키만 숨기더라도 대사와 단서 데이터 전체를 읽어 추리할 수 있다. 따라서 치팅을 막으려면 진행하지 않은 콘텐츠를 클라이언트에 내려보내지 않는 구조가 필요하다.

LLM 롤플레잉은 API 키를 클라이언트에 둘 수 없어 서버를 거쳐야 하고, 모바일·Steam 빌드는 게임 파일이 사용자 기기에 설치되어 클라이언트 측 숨김이 더 약해진다. 치팅 방지, LLM 심문, 수익화, 플랫폼 확장이 모두 같은 서버를 공통 기반으로 삼는다.

## 전제

- public 저장소 노출은 고려하지 않는다.
- git 이력은 공개 상태로 유지한다. 이미 커밋된 시나리오의 정답과 대사는 이력에 남는다.
- 기존 시나리오 3개(백야장 독살 사건, 커튼콜, 마지막 불빛)도 서버 이전 대상에 포함한다.

## 서버 구성

서버는 Cloudflare Workers와 TypeScript로 구현한다. 세션 상태는 Durable Objects에 두는데, 목숨 차감처럼 순서가 중요한 상태를 세션 단위로 일관되게 처리하기 위해서다. KV는 최종 일관성 모델이라 세션 상태 저장에 쓰지 않는다.

- LLM 호출은 Workers에서 `@anthropic-ai/sdk`로 수행하고 API 키는 Workers secret에 둔다.
- 프론트엔드는 기존 GitHub Pages 배포를 유지한다.

## 단계별 방향

### 1단계. 서버 이전

시나리오 데이터와 판정 로직을 서버로 옮긴다. 클라이언트는 조사, 제시, 고발 같은 행동만 보내고 결과 텍스트만 받는다.

- 서버가 세션 상태를 관리해 획득하지 않은 단서는 제시할 수 없게 한다.
- 목숨(촛불) 횟수를 서버가 관리해 고발 조합 대입을 막는다.
- `js/game.js`의 동기 데이터 접근을 비동기 API 호출로 바꾼다.

### 2단계. LLM 심문

단서 해금은 서버의 결정적 로직이 판정하고, LLM은 대사 표현과 플레이어 입력 분류만 맡는다. 캐릭터 프롬프트에 진상 전체를 넣으면 프롬프트 인젝션으로 정답이 새기 때문에, 공개 가능한 정보만 프롬프트에 넣는 구조로 이를 막는다.

- 각 캐릭터 프롬프트에는 현재 진행 단계에서 공개 가능한 사실만 넣는다.
- 범인 캐릭터에게도 진상 대신 위장 진술만 준다.
- 플레이어 입력이 어떤 단서에 해당하는지는 구조화된 출력으로 분류하고, 해금 여부는 코드가 결정한다.
- 비용이 낮은 모델(Claude Haiku 5.5)로 시작하고 판당 비용을 측정한다.

### 3단계. 웹 출시

스토어 심사가 없는 웹으로 먼저 출시해 보상형 힌트 광고를 붙이고, 판당 LLM 비용과 광고 수익을 실제 데이터로 비교해 다음 확장을 결정한다.

- 사용자별 LLM 호출 한도를 둔다.
- AI 응답 신고 기능을 이 단계에서 만든다. 모바일 스토어에서 필수다.

### 4단계. 모바일

App Store와 Google Play에 앱 래퍼(Capacitor 등)로 출시한다.

- AI 생성 콘텐츠의 필터링, 신고, 사용자 차단, 연락처 공개를 갖춘다(Apple 1.2·4.7, Google Play AI-Generated Content 정책).
- 서드파티 AI로 데이터를 보낸다는 사실을 알리고 동의를 받는다(Apple 5.1.2(i)).

### 5단계. Steam (미정)

Steam 출시 여부는 미정이다. Steam onboarding 문서가 광고 기반 비즈니스 모델을 금지하므로, 출시한다면 광고 대신 힌트 인게임 구매, DLC, 유료 판매 중 하나로 수익을 내야 한다.

- 서버에서 Steam 인증 티켓을 검증해 호출 한도를 적용한다.
- Content Survey에 Live-Generated AI 콘텐츠의 guardrail을 기재한다.

## 수익 모델

힌트를 보상형 광고로 제공한다. 광고를 보지 않아도 문제를 풀 수 있고, 힌트를 원하는 플레이어만 광고를 시청한다.

Apple 3.1.1은 돈을 받고 기능을 열 때 인앱 구매를 요구하므로, 힌트를 판매하지 않으면 문구상 인앱 구매는 필수가 아니다. 3.2.2(x)는 광고 시청에 대한 보상을 허용한다. 다만 3.1.4는 광고 활동을 기능 해제 조건으로 요구하는 것을 금지하므로, 힌트를 광고로만 열 수 있는 기능으로 볼지는 심사 해석에 달려 있다.

## 미결 사항

- 보상형 힌트만 제공할 때 인앱 구매나 광고 외 대체 경로(일정 시간 후 무료 해제 등)가 필요한지 확인해야 한다. 출시 전 App Review 문의를 검토한다.
- Steam 출시 여부를 정해야 한다.
- Steam 광고 금지 조항이 보상형 광고 단독에도 적용되는지 Valve 확인이 필요하다.
- 보상형 광고 단가와 판당 LLM 비용을 비교해 수익성을 검증해야 한다.
